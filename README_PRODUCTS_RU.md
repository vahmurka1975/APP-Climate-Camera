# Climate Camera — Android: вкладка «Продукты»

Архив исходного проекта Android Studio. Версия приложения: 1.1-products (versionCode 2).
Основан на ранее загруженных в рабочую среду исходниках APP-Climate-Camera.
Это не APK и не бинарный образ ESP32. GitHub-репозитории не изменены.

## Изменения

Существующее получение показаний климата сохранено. Добавлена вкладка «Продукты»:
30 нумерованных слотов; загрузка в первый свободный слот; первоначальный вес
в граммах; календарь даты закладки; целевая усушка (по умолчанию 38%);
контрольное взвешивание; последний вес и его дата; процент усушки;
прогноз достижения целевой усушки; полная доступная история по кнопке;
извлечение с подтверждением; CSV-экспорт доступной истории всех активных продуктов.

Данные хранятся на ESP32, а не только на телефоне. Контрольный замер отправляется
без даты: дату устанавливает контроллер. При отсутствии корректной даты ESP32
добавление и взвешивание блокируются. Дата закладки не может быть в будущем.
Роль viewer позволяет просматривать данные и сохранять CSV; изменения требуют admin.
Токен X-Climate-Token автоматически запрашивается через /api/status перед изменением.
Все HTTP-запросы выполняются последовательно, без автоматического повтора POST.
При обрыве связи после записи сначала обновите список: ESP32 мог принять запрос.

## Совместимость API

GET /api/status: token, readOnly, isoDate и существующая телеметрия.
GET /api/products: today; products — 30 объектов с id, active, initialWeight,
targetLossPct, startDate, weighings [{date, weight}].
POST /api/products/add: weight, startDate, targetLossPct. Свободный номер назначает ESP32.
POST /api/products/weigh: id, weight. Дата в запрос не передаётся.
POST /api/products/remove: id.
POST передаются как application/x-www-form-urlencoded с X-Climate-Token.
Успех операции ожидается в JSON-поле ok, сообщение — message.

## Важное ограничение прошивки

В исследованном NetworkServer.cpp версии 1.3.2 лимит — 32 контрольных взвешивания
на продукт. После лимита прошивка вытесняет старую запись. Приложение блокирует
33-ю запись, чтобы не потерять историю незаметно. Это ограничение хранилища
не исправлено данным архивом. Другие клиенты, в том числе веб-панель, могут
по-прежнему вытеснять записи. CSV содержит только данные, ещё доступные в ESP32.
Экспорт сам по себе не разрешает дальнейшую запись в этом приложении.
Для действительно длительной полной истории требуется изменение прошивки
или отдельное долговременное хранилище.

## Прогноз

Усушка = (первоначальный вес − последний вес) / первоначальный вес × 100%.
Прогноз использует среднюю потерю веса между закладкой и последним замером.
При отсутствии положительного тренда или разных дат прогноз не строится.
Это ориентир достижения заданной усушки, а не подтверждение пищевой безопасности.

## Открытие и сборка

Распакуйте архив и откройте папку ClimateCamera_Products в Android Studio.
Дождитесь Gradle Sync. Сохранены версии и настройки сборки исходного проекта:
AGP 9.4.1; Gradle wrapper 9.6.0; compileSdk/targetSdk 37; minSdk 24;
настройки Gradle JVM исходного проекта требуют Java 25.
Доступность этих зависимостей в этой среде не проверялась. Если они уже работают
в вашем текущем проекте, используйте то же окружение Android Studio.
local.properties не включён: путь к SDK должен быть настроен на вашем компьютере.

Команды из корня проекта:
Windows: gradlew.bat testDebugUnitTest assembleDebug
Linux/macOS: chmod +x gradlew && ./gradlew testDebugUnitTest assembleDebug
После успешной сборки APK: app/build/outputs/apk/debug/app-debug.apk.
Сборка требует доступа к репозиториям зависимостей и установленного Android SDK.

Если ваша рабочая копия приложения новее основы архива, сравните изменения
перед заменой. Основные изменённые файлы: MainActivity.kt, CameraTransport.kt,
ProductModels.kt, ProductsScreen.kt и app/build.gradle.kts (номер версии).
Тесты: ProductModelsTest.kt.

## Подключение

Телефон или эмулятор должны иметь сетевой доступ к ESP32. Введите адрес камеры
и существующие учётные данные. Откройте вкладку «Продукты» и нажмите «Обновить продукты».
Используйте admin для изменений. Для viewer поля записи заблокированы.
Basic Auth поверх HTTP не шифрует пароль: используйте доверенную локальную сеть,
не публикуйте контроллер напрямую в интернете.

## Проверка перед эксплуатацией

1. Сверьте температуру, влажность и обороты с веб-интерфейсом.
2. Войдите как viewer: просмотр разрешён, изменение недоступно.
3. Войдите как admin, добавьте тестовый продукт, проверьте номер, вес и дату.
4. Добавьте контрольный вес: дата должна совпасть с текущей датой ESP32.
5. Откройте историю, сохраните CSV и сверьте усушку с веб-панелью.
6. Перезапустите ESP32 и обновите список: сохранённые данные должны остаться.
7. Проверьте обработку отсутствия NTP и недоступности камеры.
8. Извлеките тестовый продукт: после подтверждения слот должен освободиться.

## Фактически выполненная проверка архива

Все Kotlin-файлы разобраны tree-sitter-kotlin без синтаксических ошибок после
нормализации расположения catch/finally. Первоначальная ошибка этого парсера
воспроизводилась даже на минимальном примере с переводом строки перед catch;
она не доказывает ошибку компилятора Kotlin в исходной записи.
XML-файлы проверены на корректность, содержимое ZIP и контрольные суммы проверены.

Компиляция Android/Gradle, JUnit-тесты, установка на эмулятор и обмен с реальной
камерой в этой среде НЕ выполнялись: Java и Android SDK отсутствуют.
Синтаксический анализ не заменяет компиляцию и не проверяет совместимость библиотек.
