# Исправление закладки нового продукта

Причина HTTP 400: ProductsScreen.kt отправлял поле weight, тогда как обработчик ESP32 /api/products/add читает initialWeight. Кодирование формы и авторизация не изменялись.

Исправлено:
- Для закладки передаётся initialWeight, для контрольного взвешивания остаётся weight.
- Выбранный свободный номер продукта передаётся как id также при закладке.
- Сохранены startDate, targetLossPct, проверка веса и поддержка запятой при вводе.

Изменён только файл app/src/main/java/com/example/climatecamera/ProductsScreen.kt среди исходников приложения. FIX_PRODUCT_ADD.patch содержит точный diff. Настройки Gradle и зависимости не менялись. Прошивка и сохранённые продукты не менялись.

## Установка
Откройте распакованный проект в Android Studio, соберите и установите приложение поверх текущего с тем же applicationId и подписью. Либо перенесите исправленный ProductsScreen.kt в свой рабочий проект и пересоберите его. Удалять приложение, стирать его данные или перепрошивать ESP32 не требуется.

## Проверка на контроллере
1. Выберите свободный слот и создайте продукт с весом 1500 г и корректной датой.
2. Проверьте появление продукта также в веб-интерфейсе ESP32.
3. Запишите контрольный вес и проверьте историю.
4. При необходимости извлеките тестовый продукт.

Выполнены статические проверки полей запросов, синтаксический разбор Kotlin и разбор XML. Полная Android-сборка, JUnit и испытания на устройстве не выполнялись: Java и Android SDK в среде отсутствуют. APK не включён. Подробности в VALIDATION.json.
