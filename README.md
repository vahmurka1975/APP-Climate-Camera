# ClimateCamera Android v1.0.5

Исходный проект на основе v1.0.4 из https://github.com/vahmurka1975/APP-Climate-Camera
Точная база: коммит 34a9e1ab45a54447bc47f931875897e920639b0e.
Версия приложения: 1.0.5; versionCode: 6; applicationId: com.example.climatecamera.

## Изменения

Добавлена вкладка «Настройки» с 11 параметрами: температура и её гистерезис, влажность и её гистерезис, длительность работы и паузы вентилятора, целевые обороты, поправки температуры/влажности, Kp и Ki. Диапазоны согласованы с обработчиком handleSetConfig из предоставленного NetworkServer.cpp. Допустимы десятичная точка и запятая. Целочисленные поля не принимают дробные значения.

Права берутся из readOnly в /api/status, а не из имени пользователя. Если поле отсутствует, запись запрещена. Перед POST повторно проверяются права, OTA, локальное редактирование, токен и изменяемые поля относительно прочитанной формы. Эта проверка уменьшает риск перезаписи чужих изменений, но не является атомарной блокировкой на ESP32. Перед отправкой показывается подтверждение. Опция «Сохранить в память ESP32 (NVS)» передаёт save=1, иначе save=0. После ответа настройки перечитываются. Автоматического повторения POST нет: при тайм-ауте сначала обновите форму и проверьте фактические значения.

После успешного получения телеметрии сохраняются адрес и логин. Пароль сохраняется только при включённом флажке «Запомнить пароль на этом устройстве». Данные зашифрованы AES-GCM, ключ находится в Android Keystore; API-токен постоянно не хранится. Настройки исключены из облачного резервного копирования и переноса; allowBackup=false. Кнопка «Забыть подключение» доступна после остановки обновления, удаляет сохранённые данные и ключ. При потере ключа введите данные заново или используйте эту кнопку.

При запуске поля восстанавливаются, но подключение начинается только после нажатия «Подключиться». Изменить запоминание пароля можно после остановки обновления; для сохранения нового выбора снова подключитесь и дождитесь успешного ответа.

Модуль продуктов (ProductsScreen.kt, ProductModels.kt) и политики соединения/актуальности из v1.0.4 сохранены без изменений. Никакие исходники прошивки ESP32 в этот архив не входят. Совместимость настроек проверялась по предоставленному NetworkServer.cpp, а не по подключённому устройству.

## Сборка и установка

Распакуйте архив в отдельную папку и откройте корень проекта в Android Studio. Используйте JDK, Gradle и Android SDK, соответствующие исходной v1.0.4: файлы настройки сборки и Gradle Wrapper сохранены из базы, изменены только versionName/versionCode и включена поддержка BuildConfig, если она требовалась. Не понижайте версии зависимостей вслепую.

После синхронизации выполните Build > Make Project либо команды:

```sh
./gradlew :app:testDebugUnitTest :app:assembleDebug
```

В Windows используйте gradlew.bat. APK после успешной сборки находится в app/build/outputs/apk/debug/. В этом архиве готового APK нет.

Для обновления поверх установленной v1.0.4 требуется тот же ключ подписи. При несовпадении подписи Android не установит обновление; удаление старого приложения удаляет его локальные данные. Сохраните рабочую копию проекта и ключи до обновления.

## Подключение

Введите адрес контроллера, логин и пароль. Поддерживаются http:// и https://, порт и окончание /api/status. Выберите сохранение пароля при необходимости и нажмите «Подключиться». Для настройки войдите с учётными данными администратора и откройте вкладку «Настройки». Обновите форму, измените одно значение, подтвердите и проверьте перечитанный результат.

Используются существующие GET /api/status, GET /api/products, POST /api/products/add, /weigh, /remove и POST /api/config. Авторизация Basic; изменения используют свежий X-Climate-Token. Защита хранения не шифрует HTTP-трафик: для удалённого доступа предпочтительны VPN или HTTPS с доверенным сертификатом. Проверка сертификатов не отключается. Не публикуйте пароли и токены в отчётах.

## Проверка перед использованием

Проверьте вход администратора и изменение одной уставки с повторным чтением. Проверьте вход viewer: запись должна быть недоступна. Проверьте NVS после перезапуска ESP32. Проверьте восстановление полей после закрытия приложения, варианты с паролем и без него и удаление подключения. Затем проверьте добавление, взвешивание и извлечение тестового продукта, потерю сети и индикацию устаревших данных.

## Фактически выполненные проверки

Выполнены синтаксический разбор Kotlin-файлов через tree-sitter, разбор XML, сверка неизменности модуля продуктов и политик с точной базой v1.0.4, контроль содержимого ZIP и SHA-256. Это статические проверки, не Kotlin-компиляция, не Android Lint и не испытания на устройстве. В среде подготовки нет Java и Android SDK: Gradle-сборка, unit-тесты и инструментальные тесты НЕ запускались. Существующие и добавленные тесты включены как исходники.

Подробные результаты находятся в VALIDATION_v1.0.5.json. UPDATE_v1.0.5.patch содержит изменения относительно указанного коммита. Старые файлы RELEASE, UPDATE, VALIDATION и SHA256SUMS с версиями 1.0.2–1.0.4 сохранены как история; их результаты не относятся к этому выпуску.
