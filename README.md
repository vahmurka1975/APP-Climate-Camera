# ClimateCamera Android v1.0.8 — исходники

База: APP-Climate-Camera, коммит `195764a99893a32477fc034d8bccb97a5ade8a2a`.
Версия: `1.0.8`, versionCode: `9`, applicationId: `com.example.climatecamera`.
Это исходный проект для Android Studio, не готовый APK. Прошивка ESP32 не изменена.

## Что добавлено

Вкладка «Архив» с локальным SQLite-хранилищем. Архив читается без подключения к камере. Для каждой копии сохраняются отдельный UUID, дата сохранения по телефону, отпечаток адреса камеры, начальный вес, цель усушки, дата закладки и доступные взвешивания. Можно просматривать историю, менять название и заметки, сохранять CSV через системный выбор файла и отправлять CSV через «Поделиться».

Перед извлечением приложение повторно читает права, токен и продукт. Если данные изменились, требуется обновить список и подтвердить операцию заново. Сначала копия синхронно сохраняется в SQLite, и только затем отправляется один POST /api/products/remove. Если сохранить копию не удалось, POST не отправляется. Успешный ответ ESP32 фиксируется отдельно от последующего наблюдения пустого слота.

При потере ответа копия остаётся с неподтверждённым результатом. Автоматического повторения команды нет. Во вкладке «Архив» можно только прочитать текущее состояние слота: пуст, продукт совпадает или слот изменился. Это наблюдение, а не доказательство выполнения прежней команды. Проверка доступна при подключении к тому же адресу камеры. После наблюдения пользователь может вернуться к продуктам и отдельно подтвердить новую операцию, если это действительно необходимо.

## Ограничения

Архив создаётся только при извлечении через эту версию приложения. Извлечение через веб-интерфейс или другой телефон не архивируется. В архив попадают только записи, которые ESP32 ещё хранит: его предел 32 взвешивания не увеличен, ранее потерянные записи не восстанавливаются. Постоянной синхронизации активных продуктов и общего архива между телефонами нет.

Локальная база находится в приватной папке приложения, но отдельного шифрования базы в этой версии нет. Удаление приложения или очистка данных удаляет архив. База исключена из штатного резервного копирования/переноса. CSV — экспорт для просмотра, импорт или восстановление базы из CSV не реализованы. В CSV входят ваши названия и заметки: не записывайте в них секреты. Адрес камеры представлен SHA-256-отпечатком; автоматически пароли и API-токены не экспортируются.

Разные адреса одного ESP32 считаются разными источниками. Прошивка не даёт уникальный идентификатор партии, поэтому после изменения или повторного использования слота приложение не может достоверно восстановить судьбу прежней партии. Повторная ручная попытка извлечения может создать ещё одну архивную копию; записи различаются UUID и статусом.

Архив пока не предназначен как единственное место хранения важных данных. Сохраняйте CSV вне приложения и не удаляйте рабочую установку без необходимости.

## Проверки именно этого выпуска

Выполнена настоящая Kotlin/JVM-компиляция семи платформонезависимых файлов приложения и восьми файлов unit-тестов. JUnit: **64 теста успешно**. Проверен XML ресурсов и манифеста, номер версии, состав архива и контрольные суммы.

Полная Gradle-сборка Android/Compose, Android Lint, инструментальные тесты SQLite/FileProvider, проверка на телефоне и ESP32 **не выполнялись**: Android SDK в среде подготовки отсутствует. Успешные JVM-тесты не являются подтверждением успешной Android-сборки. APK не создавался. Логи: verification/v1.0.8; отчёт: VALIDATION_v1.0.8.json. Старые отчёты относятся к прежним версиям.

## Установка исходников и проверка

1. Сохраните рабочую v1.0.7, ключ подписи и текущие локальные изменения. Не удаляйте приложение на телефоне без необходимости.
2. Распакуйте ZIP в отдельную папку, откройте корень в Android Studio и выполните Gradle Sync. Версии AGP, Gradle, Compose и SDK сохранены из вашего репозитория; не понижайте их вслепую.
3. Выполните `gradlew.bat :app:testDebugUnitTest :app:assembleDebug` (Windows) либо `./gradlew :app:testDebugUnitTest :app:assembleDebug` (Linux/macOS).
4. Устанавливайте обновление с тем же applicationId и тем же ключом подписи. Если сборка останавливается, сохраните полный текст ошибки; не заменяйте рабочий APK непроверенной сборкой.
5. Пройдите сценарии из docs/ACCEPTANCE_v1.0.8_RU.md на тестовом продукте.
6. После проверки переносите изменения в свою клонированную Git-папку. Не копируйте поверх неё папку .git, local.properties, .idea или build. Просмотрите diff, затем Commit и Push. Существующий GitHub Actions после Push может выполнить Android-сборку в вашем репозитории; здесь его результат не проверялся.

UPDATE_v1.0.8.patch — альтернативный способ переноса относительно указанной базы. Не применяйте его поверх уже скопированных изменений. SHA256SUMS_v1.0.8.txt содержит контрольные суммы файлов выпуска.
