# ClimateCamera Android v1.0.9 — исходники

Версия приложения: **1.0.9**, `versionCode = 10`, `applicationId = com.example.climatecamera`. База: коммит `abcfd6638e5f71243bb91fd95a869632bbf04d7b` репозитория APP-Climate-Camera.

Это архив исходников для Android Studio, не готовый APK. Изменения не отправлены в GitHub. Прошивка ESP32 не изменена.

## Что изменилось

- Бирюзовая светлая и тёмная темы; выбор по системной теме. Динамическая палитра Android по умолчанию отключена для единого оформления.
- Обновлены типографика и скругления карточек. Общая тема применяется ко всем вкладкам, но отдельная переработка экранов продуктов, архива и настроек в этот этап не входит.
- Нижняя навигация: «Камера», «Продукты», «Архив», «Настройки».
- Форму подключения можно свернуть и раскрыть нажатием на карточку состояния.
- Крупные показатели температуры и влажности; при достаточной ширине карточки располагаются рядом.
- Отдельные блоки вентилятора, оборудования и раскрываемых технических сведений.
- Сохранены предупреждения об устаревших данных и остановке обновления. Старые значения не должны восприниматься как текущие.

Сетевой транспорт, хранилище архива, операции с продуктами и их политики побайтно совпадают с базовой v1.0.8. Значок приложения сохранён из базы. Новые разрешения и зависимости не добавлены. Версии AGP, Gradle, Kotlin, Compose и SDK не менялись.

## Реально выполненные проверки

Выполнены Kotlin/JVM-компиляция семи платформонезависимых файлов и восьми файлов тестов, затем JUnit: **64 теста, 0 ошибок**. Официальным Kotlin-парсером проверены **27 Kotlin-файлов, синтаксических ошибок нет**. Разобраны **11 XML-файлов**. Сверены номер версии, неизменность логики и состав ZIP.

Полная Android/Compose-сборка, Android Lint, инструментальные тесты и проверка на телефоне с ESP32 **не выполнены**: Android SDK здесь не настроен. Успешные JVM-тесты и синтаксический анализ не доказывают успешной Android-сборки. APK этого выпуска не создавался; старый `app/debug` исключён, чтобы не перепутать его с новым результатом. Логи находятся в `verification/v1.0.9`, отчёт — `VALIDATION_v1.0.9.json`. Старые отчёты и контрольные суммы относятся к прежним выпускам.

## Как открыть и проверить

1. Сохраните рабочую v1.0.8, локальные изменения и ключ подписи. Если архив продуктов важен, заранее экспортируйте CSV и сохраните его вне приложения. Не удаляйте приложение и не очищайте его данные.
2. Распакуйте ZIP в отдельную папку и откройте её корень в Android Studio: рядом должны находиться `settings.gradle.kts`, `gradlew.bat` и папка `app`.
3. Выполните Gradle Sync. Не понижайте версии инструментов и SDK вслепую.
4. В терминале Android Studio на Windows выполните `./gradlew.bat :app:testDebugUnitTest :app:assembleDebug`; в PowerShell также допустимо `.\gradlew.bat :app:testDebugUnitTest :app:assembleDebug`. На Linux/macOS: `chmod +x gradlew` и `./gradlew :app:testDebugUnitTest :app:assembleDebug`.
5. Только после успешной сборки используйте новый `app/build/outputs/apk/debug/app-debug.apk`. Для установки поверх существующей версии необходим тот же ключ подписи. Debug-ключ на другом компьютере может отличаться; если Android отклоняет обновление, не удаляйте рабочее приложение ради обхода ошибки.
6. Пройдите сценарии из `docs/ACCEPTANCE_v1.0.9_RU.md`. Не проверяйте извлечение на важном продукте.

## Как перенести в существующий репозиторий

1. Убедитесь, что рабочая Git-папка соответствует указанному базовому коммиту, либо отдельно сравните более новые изменения. Если репозиторий уже обновился, не копируйте файлы поверх него вслепую.
2. Перенесите изменения из архива, сохранив вашу папку `.git`, `local.properties`, настройки среды и ключ подписи. ZIP не содержит Git-истории. Не переносите и не публикуйте локальные сборки.
3. Альтернатива копированию — `UPDATE_v1.0.9.patch`. Сначала проверьте `git apply --check ПУТЬ_К_PATCH`, затем примените `git apply ПУТЬ_К_PATCH`. Используйте один способ, а не копирование и патч одновременно. Патч переносит текстовые изменения; старый отслеживаемый APK он намеренно не удаляет.
4. Просмотрите diff, выполните локальную сборку и проверку приложения. После этого сделайте Commit and Push. Результат GitHub Actions необходимо проверить отдельно: здесь его запуск не подтверждён.

## Ограничения, которые не изменились

Архив хранится локально и не синхронизируется между телефонами. Предел истории ESP32 в 32 взвешивания не увеличен. Потерянные ранее записи не восстанавливаются. Удаление приложения или очистка данных удаляют локальный архив; CSV не является поддерживаемым импортом/восстановлением базы.

`SHA256SUMS_v1.0.9.txt` содержит контрольные суммы файлов архива, кроме самих двух файлов текущих контрольных сумм. `UPDATE_v1.0.9.patch` подготовлен относительно указанной базы.
